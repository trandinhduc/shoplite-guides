## Lý thuyết nhanh

### Một test Playwright gồm những gì

```ts
import { test, expect } from "../fixtures"; // test + expect, kèm fixture riêng của dự án

test("đúng 500.000đ: miễn phí giao hàng", { tag: "@GH-4" }, async ({ page, shop }) => {
  await shop.addToCart("ban-di-chuot-deskmat-xl", 2); // fixture tự viết: chuẩn bị chung
  await page.goto("/cart"); // đường dẫn tương đối, baseURL lấy từ config
  await expect(page.getByTestId("cart-total")).toHaveText("500.000 ₫"); // assertion tự chờ
});
```

| Thành phần                 | Ý nghĩa                                                                                                              |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `test`, `test.describe`    | Một kịch bản, một nhóm kịch bản. Tên viết tiếng Việt, mô tả hành vi (quy tắc `.claude/rules/testing.md` của Module 1) |
| `{ tag: "@GH-4" }`         | Nhãn nối test với tiêu chí. Lọc bằng `--grep @GH-4`                                                                  |
| Fixture `page`, `request`  | Playwright tự tạo cho mỗi test: một tab trình duyệt **mới tinh**, một client gọi API                                 |
| Fixture tự viết (`shop`)   | Việc chuẩn bị dùng chung: thêm vào giỏ, điền form, đặt hàng                                                          |
| Locator (`getByRole`...)   | Cách tìm phần tử. **Chưa** tìm ngay - chỉ tìm khi có hành động hoặc assertion                                        |
| `await expect(...).toX()`  | Assertion **tự chờ** tới khi đúng (mặc định 5 giây, bài này đặt 10 giây). Không cần `waitForTimeout`                 |

### Tìm phần tử như người dùng tìm

Tìm theo **vai trò và tên**. Test đỏ khi người dùng thấy thay đổi, không đỏ khi dev đổi class.

| Cách tìm      | Ví dụ trên ShopLite                                                  | Test đỏ khi                                                        |
| ------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `getByRole`   | `getByRole("button", { name: "Thêm vào giỏ" })`                      | Nút đổi chữ hay đổi vai trò. **Đỏ là đúng**                        |
| `getByLabel`  | `getByLabel(/Số điện thoại/)`                                        | Nhãn của ô nhập đổi                                                |
| `getByText`   | `getByText("Sản phẩm tạm hết hàng. Vui lòng quay lại sau.")`         | Câu chữ đổi                                                        |
| `getByTestId` | `getByTestId("cart-total")`                                          | Có người xóa `data-testid` (phải cố ý mới xóa)                     |
| CSS, XPath    | `locator("main div.rounded-2xl > button.bg-indigo-600")`             | Đổi bố cục, đổi class Tailwind, thêm một thẻ `div`                 |
| Thứ tự        | `getByTestId("product-card").first()`                                | Thứ tự đổi. Danh mục mặc định xếp theo _Nổi bật_ rồi lượt đánh giá |

Hai bẫy riêng của ShopLite:

- Nút _Thêm vào giỏ_ có ở **mọi** thẻ sản phẩm, kể cả mục _Sản phẩm liên quan_ ngay dưới trang chi tiết.
  Khoanh vùng trước: `page.getByTestId("purchase-panel").getByRole("button", { name: "Thêm vào giỏ" })`
  (đúng quy tắc E2E trong `.claude/rules/testing.md` của Module 1).
- `{ name: "Đặt hàng" }` **không phân biệt hoa thường và khớp chuỗi con**: nó khớp cả nút _"Xác nhận đặt
  hàng"_ nếu sau này có. Thêm `exact: true` khi cần đúng một nút.

### Dữ liệu test: giỏ hàng tự sạch, đơn hàng thì không

- **Giỏ hàng** nằm trong `localStorage`. Mỗi test có một phiên trình duyệt mới, nên **giỏ luôn trống** khi
  test bắt đầu - không cần dọn.
- **Đơn hàng** nằm trong `storage/orders.json`, dùng chung với dev server của bạn. Không xóa được giữa các
  test, nên mỗi test kiểm đơn hàng phải **lọc theo mã đơn của chính nó** (như test mẫu
  `shopping-flow.spec.ts` đã làm).
- Không chạy được server riêng cho test: Next.js 16 từ chối chạy hai `next dev` trong cùng thư mục
  (_"Another next dev server is already running"_). Config giữ `reuseExistingServer` để dùng lại dev server
  cổng 3000.

## Bước 1 - Nâng cấp `playwright.config.ts` (5')

Sửa file có sẵn (bản đầy đủ: [reference/playwright.config.ts](reference/playwright.config.ts)):

```diff
 export default defineConfig({
   testDir: "./e2e",
   fullyParallel: false,
+  // Test đặt hàng cùng ghi storage/orders.json, mà repository chưa an toàn khi ghi đồng thời
+  // (nợ kỹ thuật, xem FEATURE-BACKLOG) - chạy tuần tự để màu đỏ chỉ đến từ lỗi thật.
+  workers: 1,
   retries: process.env.CI ? 2 : 0,
-  reporter: process.env.CI ? "github" : "list",
+  reporter: process.env.CI ? "github" : [["list"], ["html", { open: "never" }]],
+  expect: { timeout: 10_000 },
   use: {
     baseURL: BASE_URL,
-    trace: "on-first-retry",
+    // Bằng chứng khi test đỏ: chỉ giữ lại khi hỏng để thư mục test-results gọn.
+    trace: "retain-on-failure",
+    screenshot: "only-on-failure",
+    video: "retain-on-failure",
   },
```

| Dòng                                   | Vì sao                                                                                                       |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `workers: 1`                           | Bài 6.3 sẽ cho bạn tự thấy: chạy song song làm **app** hỏng file đơn hàng, test đỏ mà không phải lỗi của test |
| `trace: "retain-on-failure"`           | Bản gốc chỉ ghi trace khi chạy lại (`on-first-retry`) mà ở máy bạn `retries` = 0 → không bao giờ có trace     |
| `screenshot`, `video`                  | Ảnh và video lúc hỏng, xem trong báo cáo HTML                                                                 |
| reporter `html`                        | `npx playwright show-report` mở báo cáo, lọc được theo tag `@GH-4`                                           |
| `expect.timeout` 10 giây               | Dev server biên dịch trang lần đầu khá lâu; 5 giây mặc định dễ đỏ oan ở lần chạy đầu                          |


| File                                       | Là gì                                                                                                 |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| `.claude/agents/playwright-test-*.md`      | 3 subagent: hướng dẫn + danh sách tool. Frontmatter đặt `model: sonnet` - đổi được nếu muốn           |

Công cụ khác: `--loop=codex`, `--loop=copilot`, `--loop=opencode`, `--loop=vscode`. Bản 1.64 **chưa** có
Gemini CLI. Nâng phiên bản Playwright thì chạy lại lệnh này (định nghĩa agent đi theo phiên bản).
Thêm `--prompts` để có thêm 4 prompt mẫu trong `.claude/prompts/` (gồm quy trình planner → generator → healer).

**Quyền cho agent.** Thêm vào file cá nhân `.claude/settings.local.json` (đã có từ bài 1.2, không commit) -
**gộp** vào mảng `allow` đang có, đừng ghi đè:

```json
{
  "permissions": {
    "allow": [
      "mcp__playwright-test",
      "Bash(npx playwright test)",
      "Bash(npx playwright test *)",
      "Bash(npx playwright trace *)",
      "Bash(npx playwright show-report *)"
    ]
  },
  "enabledMcpjsonServers": ["playwright-test"]
}
```

- `mcp__playwright-test`: cho phép mọi tool của server này (mở trang, bấm, chạy test...).
- `enabledMcpjsonServers`: tự duyệt server khai báo trong `.mcp.json`. Không có dòng này, lần đầu mở
  Claude Code sẽ hỏi _"New MCP server found in .mcp.json"_ - chọn dùng server này.

Thoát và mở lại `claude`, rồi kiểm tra:

```text

/agents     → playwright-test-planner, playwright-test-generator, playwright-test-healer
```

## Bước 3 - Seed và fixture (10')

**`e2e/seed.spec.ts`** - viết lại (ShopLite không có đăng nhập, seed chỉ cần mở trang chủ và chờ nó sẵn sàng):

```ts
import { test, expect } from "./fixtures";

// Planner và generator chạy file này trước mọi việc: mở trang chủ, chờ trang sẵn sàng.
// Giỏ hàng nằm trong localStorage nên mỗi test bắt đầu với giỏ trống (context trình duyệt mới).
test("seed", async ({ page }) => {
  await page.goto("/");
  await expect(
    page.getByRole("heading", { name: "Đồ công nghệ chất lượng, giá tốt mỗi ngày" }),
  ).toBeVisible();
});
```

> 💡 Generator **chép dòng import của seed** vào mọi test nó viết. Seed import từ `./fixtures` thì test sinh
> ra cũng dùng fixture của dự án (test trong thư mục con cần `../fixtures` - xem bài 6.4).

**`e2e/fixtures.ts`** - tạo file theo khung dưới. Phần `addToCart` để trống là **bài tập** (tự viết hoặc
nhờ agent):

```ts
import { test as base, expect, type APIRequestContext, type Page } from "@playwright/test";

/** Khách hàng hợp lệ theo checkout-schema (họ tên ≥ 2 ký tự, SĐT Việt Nam, địa chỉ ≥ 10 ký tự). */
export const KHACH_MAU = {
  fullName: "Khách E2E",
  phone: "0912345678",
  address: "12 Nguyễn Huệ, Quận 1, TP.HCM",
};

export interface ShopHelpers {
  addToCart(slug: string, quantity?: number): Promise<void>;
  fillCheckout(customer?: Partial<typeof KHACH_MAU>): Promise<void>;
  placeOrder(): Promise<string>;
}

function createShopHelpers(page: Page): ShopHelpers {
  return {
    async addToCart(slug, quantity = 1) {
      // TODO(lab): mở /products/<slug>, tăng số lượng trong khối purchase-panel,
      // bấm "Thêm vào giỏ", chờ nút đổi thành "Đã thêm".
    },
    async fillCheckout(customer = {}) {
      const data = { ...KHACH_MAU, ...customer };
      await page.getByLabel(/Họ và tên/).fill(data.fullName);
      await page.getByLabel(/Số điện thoại/).fill(data.phone);
      await page.getByLabel(/Địa chỉ giao hàng/).fill(data.address);
    },
    async placeOrder() {
      await page.getByRole("button", { name: "Đặt hàng" }).click();
      await expect(page).toHaveURL(/\/orders\/SL-\d{8}-[0-9A-F]{6}\?placed=1/);
      return page.url().match(/SL-\d{8}-[0-9A-F]{6}/)![0];
    },
  };
}

/** Tạo sẵn một đơn "Chờ xác nhận" qua API - dùng khi phần cần kiểm không phải là đặt hàng (ví dụ hủy đơn). */
export async function createPendingOrder(request: APIRequestContext): Promise<string> {
  const response = await request.post("/api/orders", {
    data: {
      customer: KHACH_MAU,
      shippingMethod: "standard",
      paymentMethod: "cod",
      items: [{ productId: "p010", quantity: 1 }],
    },
  });
  expect(response.status()).toBe(201);
  return ((await response.json()) as { id: string }).id;
}

export const test = base.extend<{ shop: ShopHelpers }>({
  shop: async ({ page }, provide) => {
    await provide(createShopHelpers(page));
  },
});

export { expect };
```

**Prompt** (nếu nhờ agent viết `addToCart`)

```text
Hoàn thiện hàm addToCart trong e2e/fixtures.ts: mở /products/<slug>, trong khối
getByTestId("purchase-panel") bấm "Tăng số lượng" (quantity - 1) lần, kiểm ô "Số lượng" bằng quantity,
bấm "Thêm vào giỏ" rồi chờ nút đổi thành "Đã thêm". Chỉ dùng getByRole/getByLabel/getByTestId,
không dùng waitForTimeout hay force. Không sửa phần khác của file.
```

So với đáp án: [reference/e2e/fixtures.ts](reference/e2e/fixtures.ts).

> ⚠️ **Bẫy ESLint:** tài liệu Playwright đặt tên tham số thứ hai của fixture là `use`
> (`async ({ page }, use) => { await use(...) }`). ESLint của Next.js (`react-hooks/rules-of-hooks`) tưởng
> đó là React hook và báo **error** → `npm run check` đỏ. Đặt tên khác (`provide`), **đừng tắt rule**
> (`AGENTS.md`: _"không tắt rule ESLint để cho qua"_).

```bash
npx playwright test e2e/seed.spec.ts
npm run check          # tsconfig quét cả e2e/ nên typecheck bắt được lỗi trong fixture
```

## Bước 4 - Test đầu tiên bằng `codegen` (10')

`codegen` mở một trình duyệt và **ghi lại** mọi thao tác thành code. Viết GH-1 phần "hết hàng":

```bash
npm run dev                                                        # terminal 1, nếu chưa chạy
npx playwright codegen http://localhost:3000/products?category=am-thanh   # terminal 2
```

Trên cửa sổ trình duyệt của codegen:

1. Bấm nút **Assert visibility** trên thanh công cụ, rồi bấm vào nút _Hết hàng_ trên thẻ _Micro thu âm
   PodCast USB_.
2. Bấm tên sản phẩm _Micro thu âm PodCast USB_.
3. **Assert text**, bấm vào dòng _"Sản phẩm tạm hết hàng. Vui lòng quay lại sau."_.

Chép code từ cửa sổ Inspector vào `e2e/gio-hang/them-san-pham.spec.ts`, rồi **dọn** (codegen chỉ ghi lại,
không biết tiêu chí):

- [ ] Đổi import sang `import { test, expect } from "../fixtures";`
- [ ] Bọc trong `test.describe("Giỏ hàng và phí giao hàng", ...)`, đặt tên test tiếng Việt, thêm `{ tag: "@GH-1" }`.
- [ ] Thay mọi `locator("...")` dạng CSS bằng `getByRole`/`getByTestId(...).filter({ hasText })`.
- [ ] Thêm kiểm tra mà codegen không ghi được: nút _Hết hàng_ **bị vô hiệu** (`toBeDisabled()`), trang chi
      tiết **không có** khối mua (`expect(page.getByTestId("purchase-panel")).toHaveCount(0)`).
- [ ] Mỗi bước một comment, đánh số theo tiêu chí.

Viết tiếp test GH-1 thứ hai (thêm 3 × SwiftClick, giỏ báo 3 sản phẩm) - bằng codegen, bằng tay, hoặc nhờ
agent. Đối chiếu: [reference/e2e/gio-hang/them-san-pham.spec.ts](reference/e2e/gio-hang/them-san-pham.spec.ts).

```bash
npx playwright test --grep @GH-1
```
