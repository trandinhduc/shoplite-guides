# 6.4 - Sinh bộ test từ tiêu chí bằng Planner, Generator và Healer

**Thời lượng:** 50 phút · **Kết quả:** kế hoạch `specs/mua-hang.plan.md` phủ đủ 7 tiêu chí (Bảng A); ít nhất
9 test E2E mới do generator sinh, mỗi test mang tag tiêu chí; cả bộ xanh 3 lần liên tiếp; ít nhất một bản
vá của healer được duyệt (Bảng B); bộ test đạt ≥ 8/10 theo checklist chất lượng (Bảng D).

> 🎬 **Gợi ý demo (12'):** kịch bản chi tiết từng phút ở [reference/kich-ban-demo.md](reference/kich-ban-demo.md)
> (cảnh 2-4). Điều lớp cần thấy: planner **tự bấm** khắp ShopLite trong một cửa sổ trình duyệt, generator
> **làm lại từng bước** trước khi ghi file, healer chỉ đổi đúng **một dòng locator** khi nhãn nút đổi có chủ ý.

## Lý thuyết nhanh

### Ba agent, giao nhau bằng file

Playwright góp **hướng dẫn và công cụ** (MCP server `playwright-test`). Mô hình AI là của công cụ bạn dùng
(ở đây Claude Code; frontmatter của agent đặt `model: sonnet`).

| Agent         | Việc                                                                                                       | Đầu vào                                    | Đầu ra                                       | Tool đặc trưng                                       |
| ------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------ | -------------------------------------------- | ---------------------------------------------------- |
| **Planner**   | Chạy seed, khám phá app qua cây accessibility, nghĩ kịch bản thường, biên và lỗi                            | `specs/tieu-chi.md` + seed                 | `specs/mua-hang.plan.md`                     | `planner_setup_page`, `browser_*`, `planner_save_plan` |
| **Generator** | Với **từng** kịch bản: làm lại từng bước trên trình duyệt thật, kiểm locator và assertion ngay lúc làm, rồi ghi file | Một kịch bản trong kế hoạch + seed  | `e2e/<luồng>/<kịch bản>.spec.ts`, **mỗi kịch bản một file** | `generator_setup_page`, `generator_read_log`, `generator_write_test` |
| **Healer**    | Chạy test, dừng ở chỗ lỗi, xem snapshot, sửa và chạy lại tới khi xanh. Tin app sai thì đánh `test.fixme()` | Các test đang đỏ                           | File test đã sửa                             | `test_run`, `test_debug`, `browser_generate_locator` |

### Con người đứng ở hai chỗ nối

```text
specs/tieu-chi.md ─► planner ─► [ DUYỆT KẾ HOẠCH ] ─► generator ─► chạy test ─► healer ─► [ DUYỆT BẢN VÁ ]
                                    Bảng A                                                    Bảng B
```

- **Bảng A - Duyệt kế hoạch:** mỗi tiêu chí một dòng, kịch bản nào phủ nó. Thiếu thì bổ sung **trước** khi
  sinh test (sửa kế hoạch rẻ hơn sửa 10 file test).
- **Bảng B - Duyệt bản vá:** commit **trước** khi gọi healer, đọc diff **trước** khi commit bản vá. Chấp
  nhận hay từ chối, ghi lý do.

### Giữ tiêu chí ở đầu chuỗi

| Chỗ nối                 | Lab làm gì                                                                           |
| ----------------------- | ------------------------------------------------------------------------------------ |
| Tiêu chí → kế hoạch     | Prompt của planner kèm `specs/tieu-chi.md`; tên kịch bản bắt đầu bằng mã (`GH-4 ...`) |
| Kế hoạch → tiêu chí     | Bảng A trong `specs/bao-cao.md`                                                      |
| Test → tiêu chí         | Mỗi test mang tag: `{ tag: "@GH-4" }`                                                |
| Kết quả → tiêu chí      | Báo cáo HTML và UI mode lọc theo tag; `npx playwright test --grep @GH-4`             |

## Bước 1 - Planner viết kế hoạch (15')

Mở **phiên mới** Claude Code (`/clear`). Dev server đang chạy (`npm run dev`) - nếu chưa, MCP server sẽ tự
bật nó theo `webServer` trong config.

**Prompt**

```text
Dùng agent playwright-test-planner.
Seed: e2e/seed.spec.ts. Lưu kế hoạch vào specs/mua-hang.plan.md.

Lập kế hoạch kiểm thử cho 2 luồng trong specs/tieu-chi.md: (1) Giỏ hàng và phí giao hàng,
(2) Thanh toán và đơn hàng. Quy tắc:
- Kỳ vọng lấy từ specs/tieu-chi.md, KHÔNG lấy từ những gì app đang hiển thị. Nếu màn hình khác tiêu chí,
  vẫn ghi kỳ vọng theo tiêu chí và thêm ghi chú "APP KHÁC TIÊU CHÍ" vào kịch bản đó.
- Mỗi tiêu chí ít nhất 1 kịch bản; tên kịch bản bắt đầu bằng mã tiêu chí, ví dụ "GH-4 đúng 500.000đ: ...".
- Dùng đúng dữ liệu mẫu trong tiêu chí (tên sản phẩm, giá, tồn kho).
- Mỗi kịch bản một file riêng trong e2e/gio-hang/ hoặc e2e/dat-hang/. Riêng GH-1 đã có sẵn trong
  e2e/gio-hang/them-san-pham.spec.ts - ghi đúng file đó.
- Đơn hàng dùng chung dữ liệu với dev server: kịch bản nào kiểm đơn phải lọc theo mã đơn của chính nó.
- Không quá 12 kịch bản.
```

Điều sẽ xảy ra:

1. Planner gọi `planner_setup_page` → chạy `e2e/seed.spec.ts` → một cửa sổ Chromium mở ra (trên macOS và
   Windows trình duyệt hiện ra cho bạn xem).
2. Nó bấm khắp ShopLite: danh mục, chi tiết, giỏ, thanh toán... qua các tool `browser_*`.
3. Gọi `planner_save_plan` → file kế hoạch có cấu trúc cố định:

```markdown
### 1. Giỏ hàng và phí giao hàng

**Seed:** `e2e/seed.spec.ts`

#### 1.6. GH-4 đúng 500.000đ: miễn phí giao hàng ở giỏ hàng và trang thanh toán

**File:** `e2e/gio-hang/mien-phi-dung-nguong.spec.ts`

**Steps:**
  1. Thêm 2 Bàn di chuột cỡ lớn DeskMat XL (2 × 250.000đ) vào giỏ rồi mở /cart
    - expect: Phí giao hàng (tiêu chuẩn) là "Miễn phí"
    - expect: Tổng cộng 500.000 ₫
```

**Điền Bảng A** trong `specs/bao-cao.md`, rồi sửa kế hoạch (bằng tay hoặc nhắn planner) tới khi đủ. Lỗi hay
gặp:

| Dấu hiệu trong kế hoạch                                                  | Sửa                                                                                   |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| Có kịch bản tìm kiếm, lọc, sắp xếp - không thuộc tiêu chí nào            | Bỏ, hoặc ghi vào Bảng A là "planner tự nghĩ ra" và giải thích vì sao giữ               |
| GH-4 thiếu vế "trang thanh toán cũng miễn phí"                           | Thêm bước                                                                             |
| DH-3 thiếu vế "không cần tải lại trang", hoặc có bước "tải lại trang"    | Sửa: **bỏ** bước tải lại - đó chính là điều tiêu chí cấm                              |
| Kỳ vọng chung chung: "tổng tiền hiển thị đúng"                           | Ghi số: "Tổng cộng 500.000 ₫"                                                         |
| `File:` nằm ngoài `e2e/` (ví dụ `tests/...`)                             | Đổi về `e2e/...` - generator từ chối ghi file ngoài `testDir` của config              |
| Hai kịch bản trùng một `File:`                                           | Tách tên - generator **ghi đè** cả file mỗi lần                                        |

Đối chiếu: [reference/specs/mua-hang.plan.md](reference/specs/mua-hang.plan.md).

```bash
git add specs && git commit -m "test(e2e): test plan for cart and checkout (reviewed)"
```

## Bước 2 - Generator sinh test (15')

Phiên mới. Sinh **lần lượt**, không song song (generator dùng chung một trình duyệt).

**Prompt**

```text
Dùng agent playwright-test-generator để sinh test cho các kịch bản 1.3 tới 1.6 trong
specs/mua-hang.plan.md, lần lượt từng kịch bản (1.1 và 1.2 đã có, bỏ qua).
Quy tắc cho mọi test:
- Import test, expect từ fixtures của dự án giống seed; file trong thư mục con dùng "../fixtures".
  Dùng fixture shop (addToCart, fillCheckout, placeOrder) và createPendingOrder khi cần.
- Gắn tag mã tiêu chí ở đầu tên kịch bản: { tag: "@GH-4" }.
- Locator: getByRole / getByLabel / getByText; getByTestId khi không còn cách khác. Nút "Thêm vào giỏ"
  phải khoanh trong getByTestId("purchase-panel").
- Số liệu kỳ vọng chép từ kế hoạch, không tính lại.
```

Với mỗi kịch bản, generator: `generator_setup_page` (chạy seed) → làm từng bước trên trình duyệt →
`generator_read_log` (nhật ký các bước + locator tốt nhất + _best practices_) → `generator_write_test`. File
sinh ra mở đầu bằng:

```ts
// spec: specs/mua-hang.plan.md
// seed: e2e/seed.spec.ts
```

Xong nhóm 1, chạy lại prompt cho **2.1 tới 2.5**. Rồi:

```bash
npx prettier --write e2e specs        # generator ghi file qua MCP, hook format-file không chạy
npm run check                         # lint + typecheck quét cả e2e/
npx playwright test --grep "@GH|@DH"
```

Lỗi hay gặp ở bước này:

| Triệu chứng                                                       | Nguyên nhân                                                                    | Xử lý                                                                    |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| `Cannot find module './fixtures'`                                 | Generator chép nguyên dòng import của seed vào file trong thư mục con           | Sửa thành `../fixtures` (hoặc để healer sửa - một bản vá đáng chấp nhận) |
| `strict mode violation: getByRole('button', { name: 'Thêm vào giỏ' }) resolved to N elements` | Không khoanh vùng: thẻ _Sản phẩm liên quan_ cũng có nút này | Khoanh trong `getByTestId("purchase-panel")`                             |
| Test có `await page.waitForTimeout(...)`                          | Agent "cho chắc"                                                                | Xóa, thay bằng assertion tự chờ                                          |
| Kỳ vọng là con số lạ, khác kế hoạch                               | Agent ghi theo màn hình lúc làm                                                 | Sửa về số của tiêu chí - và ghi lại: app có thể đang sai (bài 6.5)        |
| Thiếu tag                                                         | Agent quên quy tắc                                                              | Thêm tay; nhắc lại trong prompt lần sau                                  |

Đối chiếu nội dung với [reference/e2e/](reference/e2e/) - đáp án gồm 10 file, 11 test mang tag (tên file của bạn có
thể khác, điều cần so là locator, kỳ vọng và tag).

```bash
git add e2e specs && git commit -m "test(e2e): generated tests for GH-2..GH-4, DH-1..DH-3"
```

## Bước 4 - Healer sửa test hỏng, người duyệt bản vá (15')

### 4a. Có test đỏ do chính generator sinh sai

Nếu Bước 2-3 còn test đỏ: **commit trước**, rồi phiên mới:

```text
Dùng agent playwright-test-healer: chạy các test có tag @GH hoặc @DH trong e2e/ và sửa các test đang đỏ.
Không đổi số liệu kỳ vọng (chúng lấy từ specs/tieu-chi.md). Không thêm waitForTimeout, force, retries.
Cuối cùng liệt kê ngắn gọn bạn đã sửa gì ở file nào.
```

```bash
git diff        # đọc TỪNG dòng trước khi commit
```

### 4b. Giao diện đổi có chủ ý - healer có làm đúng việc không?

Làm trên một nhánh bỏ đi, để thay đổi giao diện không lẫn vào `lab6-e2e`:

```bash
git checkout -b lab6-heal
git apply ../lab-guides/module-6-playwright-ai/reference/bugs/doi-nhan-nut-thanh-toan.diff
git commit -am "feat(cart): đổi nhãn nút thanh toán theo yêu cầu UX"     # "Tiến hành thanh toán" → "Thanh toán ngay"
npx playwright test --reporter=line                                        # GH-4 và shopping-flow đỏ
```

Phiên mới, gọi healer với prompt ở 4a (bỏ phần `@GH hoặc @DH` để chạy cả bộ). Khi soạn bài (chạy thật hai
lần, Playwright 1.64.1, Claude Code 2.1), lần nào healer cũng chỉ đổi **đúng locator** ở 2 file
`e2e/gio-hang/mien-phi-dung-nguong.spec.ts` và `e2e/shopping-flow.spec.ts` (một lần đổi luôn dòng comment
của bước):

```diff
-      await page.getByRole("link", { name: "Tiến hành thanh toán" }).click();
+      await page.getByRole("link", { name: "Thanh toán ngay" }).click();
```

Không đụng `expect` nào, không đánh `fixme`, không sửa `src/`, và tự giải thích: _"Commit ... đổi tên nút
thanh toán ... theo yêu cầu UX ... Đây là thay đổi có chủ đích, nên tôi sửa phía test, không sửa ứng dụng."_
Nó đọc được ý đồ nhờ **commit message** - một lý do nữa để viết commit message tử tế.
Diff và log đầy đủ: [reference/demo/healer-doi-nhan.ket-qua.diff](reference/demo/healer-doi-nhan.ket-qua.diff),
[reference/demo/healer-doi-nhan.ket-qua.txt](reference/demo/healer-doi-nhan.ket-qua.txt).

Điền **Bảng B** theo 4 dấu hiệu từ chối trong
[checklist](reference/checklist-chat-luong-test.md) (phần 2). Bản vá này: **chấp nhận** - giao diện đổi có
chủ ý (có commit), healer chỉ cập nhật locator.

```bash
git checkout lab6-e2e && git branch -D lab6-heal       # bỏ nhánh thử, không merge
```

> ⚠️ Hướng dẫn của healer dặn nó _"không hỏi người dùng, làm điều hợp lý nhất để test chạy được"_. Healer có
> hai kết cục: **xanh** (sửa locator, sửa cách chờ, hoặc... hạ kỳ vọng) hoặc **`test.fixme()`** khi nó tin app
> sai. Cả hai đều phải qua mắt người. Bài 6.5 cho healer gặp app có lỗi thật.

## Bước 5 - Chấm chất lượng (5')

Chấm bộ test của bạn theo [checklist 10 mục](reference/checklist-chat-luong-test.md), điền cột đầu của
**Bảng D**. Lệnh hỗ trợ:

```bash
npx playwright test --list --grep @GH-4                                  # mục 1: tiêu chí nào cũng có test
grep -rnE "waitForTimeout|force: true|networkidle|waitForLoadState" e2e  # mục 5: phải rỗng
grep -rnE "locator\(|\.nth\(|\.first\(\)" e2e                            # mục 3: xem từng chỗ có lý do không
npx playwright test --repeat-each=3                                     # mục 7
npm run check                                                           # mục 10
```

Mục 9 (_đỏ đúng chỗ_) chấm ở bài 6.5.

✅ **Checkpoint:** Bảng A đủ 7 dòng; `npx playwright test --list --grep "@GH|@DH"` ≥ 11 test (2 viết tay +
≥ 9 sinh ra); cả bộ xanh `--repeat-each=3`; `npm run check` pass; Bảng B có ít nhất bản vá của 4b; Bảng D
cột đầu ≥ 8/9 (chưa tính mục 9).

## Mở rộng (tùy chọn) - Test Architect (TEA) của BMAD

Ba agent của Playwright trả lời _"viết test thế nào"_. Câu hỏi đứng trước là _"test cái gì, ở tầng nào, kỹ
tới đâu, khi nào đủ để phát hành"_ - đó là việc của module **TEA** trong BMAD (Module 4-5). Đã cài thử:
BMAD 6.12.4 kèm TEA v1.27.2.

```bash
npx bmad-method@6.12.4 install --modules bmm,tea --tools claude-code     # hoặc chạy install, chọn Modify, tích tea
```

| Mã  | Skill                       | Làm gì                                           | Nối với Module 6                                   |
| --- | --------------------------- | ------------------------------------------------ | -------------------------------------------------- |
| TD  | `bmad-testarch-test-design` | Chấm rủi ro, xếp P0 tới P3, chọn tầng test       | Chứng minh GH-4 (tính sai tiền) đáng có E2E         |
| TF  | `bmad-testarch-framework`   | Dựng khung test, ví dụ Playwright                | Thay các bước làm tay ở bài 6.2                     |
| AT  | `bmad-testarch-atdd`        | Sinh test đỏ trước khi code                      | Module 5, nếu nhóm làm TDD                          |
| TA  | `bmad-testarch-automate`    | Mở rộng độ phủ sau khi có code                   | Cùng việc với generator                            |
| RV  | `bmad-testarch-test-review` | Chấm chất lượng bộ test từ 0 tới 100             | Duyệt bộ test agent vừa sinh (so với Bảng D)        |
| TR  | `bmad-testarch-trace`       | Truy yêu cầu tới test, ra PASS / CONCERNS / FAIL | Bản đầy đủ của Bảng A                              |

Điểm rủi ro = **xác suất × tác động** (mỗi yếu tố 1-3): 1-3 ghi lại · 4-5 theo dõi · 6-8 giảm thiểu (cổng
phát hành CONCERNS tới khi có biện pháp) · 9 chặn (FAIL). Ví dụ: _"hai đơn lưu cùng lúc làm mất đơn"_ (bài
6.3) - xác suất 2, tác động 3 → **6**, phải giảm thiểu trước khi phát hành.
