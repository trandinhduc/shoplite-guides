# 6.5 - Đọc đúng màu đỏ: test sai hay app sai?

**Thời lượng:** 25 phút · **Kết quả:** áp hai lỗi cài sẵn vào ShopLite, thấy bộ test của bạn đỏ **đúng chỗ**
trong khi 83 unit test vẫn xanh; đọc trace (bằng mắt và nhờ agent đọc bằng dòng lệnh) rồi kết luận có bằng
chứng trong **Bảng C**; thấy tận mắt một bộ test "sinh từ code" khóa lỗi vào và chập chờn.

> 🎬 **Gợi ý demo (3'):** cảnh 5 trong [reference/kich-ban-demo.md](reference/kich-ban-demo.md) - hai bộ test
> trên cùng một app có lỗi. Một bộ đỏ đúng 2 chỗ, một bộ xanh. Hỏi lớp: _"Bộ nào tốt hơn?"_

## Lý thuyết nhanh

### Xem bằng chứng trước khi sửa

Config từ bài 6.2 đã bật sẵn ba thứ, chỉ giữ lại khi test hỏng:

| Bằng chứng | Trong `playwright.config.ts`    | Trả lời câu hỏi                                             |
| ---------- | ------------------------------- | ----------------------------------------------------------- |
| Trace      | `trace: "retain-on-failure"`    | Bước nào hỏng, DOM lúc đó ra sao, API trả gì                 |
| Ảnh chụp   | `screenshot: "only-on-failure"` | Màn hình lúc hỏng                                           |
| Video      | `video: "retain-on-failure"`    | Diễn biến dẫn tới chỗ hỏng                                  |

```text
Test đỏ ─► chạy lại 3 lần ─┬─ lúc đỏ lúc xanh ─► CHẬP CHỜN: tìm nguyên nhân (bài 6.3), chưa kết luận gì
                           └─ đỏ cả 3 lần ─► mở trace ─► đối chiếu specs/tieu-chi.md
                                                ├─ app làm ĐÚNG tiêu chí, test cũ/sai ─► TEST SAI ─► healer, rồi duyệt bản vá
                                                └─ app làm SAI tiêu chí ──────────────► APP SAI ──► GIỮ ĐỎ, báo lỗi, sửa app
```

### Healer có thể kết thúc thế nào

| Kết cục                         | Ví dụ trên ShopLite                                                                 | Người duyệt hỏi                         | Chấp nhận khi                          |
| ------------------------------- | ----------------------------------------------------------------------------------- | --------------------------------------- | -------------------------------------- |
| Xanh nhờ sửa cách tìm           | `"Tiến hành thanh toán"` → `"Thanh toán ngay"` (bài 6.4)                            | Giao diện đổi có chủ ý không?           | Có commit / yêu cầu đổi nhãn            |
| Xanh nhờ **đổi kỳ vọng**        | `"Miễn phí"` → `"30.000 ₫"`; thêm `page.reload()` trước khi kiểm _Đã hủy_            | Kỳ vọng mới có khớp tiêu chí không?     | **Gần như không bao giờ**               |
| `test.fixme()` kèm ghi chú      | Đánh dấu bỏ qua GH-4, ghi chú "app tính phí ở đúng ngưỡng"                          | Đúng là app sai? Đã báo lỗi chưa?       | Có phiếu lỗi và hạn gỡ `fixme`          |
| Không sửa, báo lỗi app          | Báo "commit refactor đổi `>=` thành `>`", hỏi có muốn sửa app không                 | Chẩn đoán có đúng không?                | Đối chiếu trace + tiêu chí thấy đúng    |

Hướng dẫn của healer dặn: _"không hỏi người dùng, làm điều hợp lý nhất để test chạy được"_ và cho phép
`test.fixme()`. Nó **luôn tự quyết** - vì vậy **không cho healer tự sửa trong CI**: ở đó không ai đọc diff,
và build đỏ là tín hiệu duy nhất. Quy trình đúng: CI đỏ → dev chạy healer trên máy → bản vá vào pull request →
người khác duyệt.

## Bước 1 - Áp hai lỗi cài sẵn (5')

Hai bản vá được viết để trông như một lần "dọn code" bình thường. **Đừng mở file `.diff` trước khi điền xong
Bảng C.**

```bash
git checkout lab6-e2e && git status                 # phải sạch
git checkout -b lab6-bug
git apply ../lab-guides/module-6-playwright-ai/reference/bugs/bug-1-mien-phi-giao-hang.diff
git apply ../lab-guides/module-6-playwright-ai/reference/bugs/bug-2-huy-don.diff
git commit -am "refactor: gọn code giỏ hàng và hủy đơn"

npm run check                                       # unit test?
npx playwright test --reporter=line                 # E2E?
```

Ghi lại: bao nhiêu unit test đỏ? Bao nhiêu E2E đỏ, của tiêu chí nào? Hai test mẫu trong `shopping-flow.spec.ts`
có bắt được gì không?

## Bước 3 - Nhờ agent đọc trace, chỉ phân tích (7')

Phiên Claude Code mới. Agent dùng lệnh `npx playwright trace` (đã cho phép ở bài 6.2):

**Prompt**

```text
Đọc trace của test "DH-3 hủy đơn chờ xác nhận" trong test-results/ bằng npx playwright trace
(open, actions, action, requests, snapshot <số> --phase after snapshot, close).
CHỈ phân tích, không sửa file nào. Trả lời:
1. Action nào hỏng (số thứ tự trong trace) và lỗi là gì.
2. Trang hiển thị gì ngay sau action đó.
3. PATCH /api/orders/<mã> trả mã HTTP nào.
4. Theo specs/tieu-chi.md (DH-3) thì đây là lỗi của test hay của app. Trích bằng chứng.
```

Lặp lại cho test GH-4 (thay câu 3 bằng: _"giỏ hàng hiện phí giao hàng và tổng cộng bao nhiêu"_).

Kết luận mong đợi:

| Test | Bằng chứng                                                                                                  | Kết luận                                     |
| ---- | ----------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| DH-3 | `PATCH` trả **200**; sau 10 giây tiêu đề vẫn _"Đơn hàng SL-... Chờ xác nhận"_, nút _Hủy đơn hàng_ vẫn còn    | **App sai**: server đã hủy, giao diện không làm mới (tiêu chí: "đổi ngay, không cần tải lại") |
| GH-4 | Giỏ 500.000 ₫: thông báo _"được miễn phí giao hàng"_ nhưng phí 30.000 ₫, tổng 530.000 ₫; trang thanh toán vẫn miễn phí | **App sai**: giỏ hàng tính sai đúng ở ngưỡng (tiêu chí: "đúng bằng 500.000 ₫ thì miễn phí") |

Điền **Bảng C** trong `specs/bao-cao.md`, kèm câu trả lời: vì sao GH-1..GH-3, DH-1, DH-2 **vẫn xanh là đúng**?
(Gợi ý: hai lỗi chỉ chạm ngưỡng đúng 500.000 ₫ ở giỏ hàng và bước làm mới sau khi hủy; những tiêu chí khác
không đi qua hai chỗ đó.)

## Bước 4 - Nếu giao cho healer thì sao? (3', tùy chọn)

Code đã commit nên thử thoải mái:

```text
Dùng agent playwright-test-healer: chạy toàn bộ test trong thư mục e2e/ và sửa các test đang đỏ.
Cuối cùng liệt kê ngắn gọn bạn đã sửa gì ở file nào.
```

```bash
git diff
```

Khi soạn bài, chạy thật hai lần, cả hai lần healer **không sửa file nào**: nó chỉ ra đúng `>` thay cho `>=` ở
`cart-summary.tsx` và dòng `router.refresh()` bị xóa, rồi hỏi có muốn sửa app không
([log](reference/demo/healer-app-co-loi.ket-qua.txt)). Nó đoán được nhờ commit ngay trước có tên "refactor"
và diff nhỏ. Đừng coi đó là bảo đảm: lỗi nằm lẫn trong một commit lớn, hoặc chưa commit, thì healer có thể
đánh `fixme` hoặc "sửa" kỳ vọng. Nếu diff của bạn có bất kỳ dấu hiệu nào trong 4 dấu hiệu từ chối
([checklist](reference/checklist-chat-luong-test.md), phần 2) → **từ chối**, ghi vào Bảng B, rồi bỏ thay đổi:

```bash
git checkout -- e2e
```

## Bước 5 - Cảnh so sánh: bộ test sinh từ code (5')

File [reference/demo/sinh-tu-code.spec.ts](reference/demo/sinh-tu-code.spec.ts) là 3 test được viết **theo code
đang có lỗi**, không có tiêu chí: kỳ vọng chép đúng những gì code đang làm.

```bash
mkdir -p e2e/tu-code
cp ../lab-guides/module-6-playwright-ai/reference/demo/sinh-tu-code.spec.ts e2e/tu-code/
npx playwright test e2e/tu-code --repeat-each=3 --reporter=line       # app ĐANG có lỗi
git revert --no-edit HEAD                                              # gỡ 2 lỗi
npx playwright test e2e/tu-code --reporter=line                        # app ĐÃ đúng
npx playwright test --grep "@GH|@DH" --reporter=dot                    # bộ từ tiêu chí
```

Kết quả khi soạn bài:

| Bộ test                        | App có 2 lỗi                                                                | Gỡ lỗi                                                         |
| ------------------------------ | --------------------------------------------------------------------------- | -------------------------------------------------------------- |
| **Sinh từ code** (3 test)      | 2 test luôn xanh; test _"hủy đơn rồi tải lại"_ **chập chờn** (đỏ khoảng một nửa số lần) | **Đỏ 1**: _"500.000đ ... vẫn cộng phí 30.000đ"_ - bộ test **bảo vệ lỗi** |
| **Sinh từ tiêu chí** (11 test) | **Đỏ đúng 2**: GH-4, DH-3                                                    | Xanh 11                                                        |

Vì sao test _"hủy đơn rồi tải lại"_ chập chờn? Nó chờ nút _Xác nhận hủy_ biến mất - nhưng nút đổi chữ thành
_"Đang hủy…"_ **ngay khi bấm**, nên test tưởng xong rồi tải lại trang trước khi server kịp hủy. Đây là kiểu
**test sai** (chờ sai tín hiệu). Test DH-3 của bộ tiêu chí chờ đúng tín hiệu: `page.waitForResponse` của lệnh
`PATCH`.

Dọn dẹp:

```bash
rm -r e2e/tu-code
git checkout lab6-e2e && git branch -D lab6-bug
git status                                          # phải sạch
```

Chấm mục 9 (_đỏ đúng chỗ_) trong **Bảng D**.

✅ **Checkpoint:** Bảng C có 2 dòng, cả hai kết luận **app sai** kèm bằng chứng từ trace (mã HTTP của `PATCH`,
nội dung màn hình); giải thích được vì sao 9 test còn lại xanh là đúng; nếu đã thử Bước 4, Bảng B có thêm
một dòng; nhánh `lab6-bug` đã xóa, `lab6-e2e` sạch.
