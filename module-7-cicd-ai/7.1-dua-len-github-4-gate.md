## Lý thuyết nhanh

### CI là gì, gate là gì

**CI** (tích hợp liên tục) là một máy trên GitHub tự chạy kiểm tra **mỗi lần có người đẩy code**. Một **gate**
là một kiểm tra mà nếu đỏ thì PR **không được merge**. Gate phải **tất định**: cùng code, chạy hai lần, ra cùng
kết quả. AI không tất định: cùng một PR, hai lần chạy có thể nhận xét khác nhau. Vì vậy:

| Câu hỏi                 | Gate tất định (bài 7.1)                                   | AI (bài 7.3, 7.4)                                       |
| ----------------------- | --------------------------------------------------------- | ------------------------------------------------------- |
| Cùng code, chạy hai lần | Cùng kết quả                                              | Có thể ra hai nhận xét khác nhau                        |
| Giỏi bắt                | Lỗi đo được: luật lint, test đỏ, khoá trong commit       | Lỗi cần hiểu nghiệp vụ: làm sai spec, thiếu test        |
| Khi vắng mặt            | PR **không** merge được                                   | PR vẫn đi tiếp, chỉ thiếu nhận xét                      |
| Vai trò                 | **Quyết định** (check bắt buộc của `main`, bài 7.6)       | **Nhận xét và giải thích**                              |

### Bốn gate của ShopLite

| Gate      | Kiểm gì                                                                                                    | Công cụ                                                  | Đỏ khi nào (ví dụ trên ShopLite)                                      |
| --------- | ---------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- | --------------------------------------------------------------------- |
| `lint`    | Cách viết code + **luật bảo mật và kiến trúc của nhóm** + kiểu TypeScript                                  | ESLint (`npm run lint`), `tsc` (`npm run typecheck`)     | Dựng `new RegExp(q)` từ từ khóa khách gõ (luật **BM-1**)              |
| `unit`    | 83 unit test + **sàn coverage**                                                                            | Vitest (`npx vitest run --coverage`)                     | Một quy tắc tính tiền bị sửa sai; coverage tụt dưới 60%               |
| `e2e`     | 14 test E2E (11 của Module 6 + seed + 2 có sẵn), test đỏ được chạy lại 1 lần, **chập chờn vẫn tính là đỏ** | Playwright (`--retries=1 --fail-on-flaky-tests`)         | Giỏ đúng 500.000 ₫ bị tính phí giao hàng (tiêu chí GH-4)              |
| `bao-mat` | **Khoá, token, mật khẩu trong cả lịch sử commit** + thư viện có lỗ hổng mức cao                            | **gitleaks 8.30.1** + `npm audit --audit-level=high`     | Một commit (kể cả đã bị xóa ở commit sau) có `SHIPPING_API_KEY = "..."` |

**Công cụ quét bảo mật chính: [gitleaks](https://github.com/gitleaks/gitleaks).** Một file chạy duy nhất, miễn phí,
không cần tài khoản, chạy giống hệt ở máy và trên CI, quét **toàn bộ lịch sử git** chứ không chỉ code hiện tại.
`npm audit` có sẵn trong npm, bổ sung phần thư viện. (Bài 7.5 thêm 2 công cụ tự viết vào gate này: soát workflow
và quét câu mồi cho AI.)

> 💡 Vì sao không dùng `gitleaks-action`? Action đó đòi license khi repo thuộc một organization. Gọi thẳng CLI,
> **ghim phiên bản và kiểm checksum** thì vừa miễn phí vừa an toàn hơn.

### "Xanh ở máy = xanh trên CI"

Cả máy bạn lẫn CI chạy **cùng một script**: `scripts/ci/gate.mjs`. Workflow chỉ cài đặt rồi gọi script đó. Nhờ vậy
trước khi đẩy code bạn chạy `node scripts/ci/gate.mjs all` là biết trước CI sẽ nói gì. Script còn ghi
`gate-<tên>.log` và `gate-<tên>.json` để bài 7.4 đưa cho AI đọc khi có gate đỏ.

## Bước 2 - Fork repo mẫu và đẩy `main` (10')

Làm **theo cặp**: mỗi người một fork, người kia là người duyệt PR (bài 7.6). Đăng nhập GitHub CLI nếu chưa:
`gh auth login`.

Repo của bạn trong Module 7 là một **fork** của repo mẫu <https://github.com/trandinhduc/shoplite>, nằm trên tài
khoản GitHub của bạn. Fork của repo public luôn **public**, nên ruleset của bài 7.6 dùng được trên tài khoản Free.
(ShopLite là mã nguồn mẫu giấy phép MIT, không có gì bí mật; secret của GitHub Actions vẫn được bảo vệ trên repo
public.)

### 2a. Fork từ thư mục đang làm

Đứng trong thư mục `shoplite` bạn đã làm từ Module 1 (clone từ repo mẫu, `main` đã có Module 1 và bộ E2E):

```bash
git remote -v                                        # origin đang là trandinhduc/shoplite
gh repo fork --remote                                # tạo <ten-ban>/shoplite; origin = fork của bạn, upstream = repo mẫu
gh repo view --json nameWithOwner --jq .nameWithOwner   # trandinhduc/shoplite: gh đang nhắm repo của GIẢNG VIÊN
git remote -v                                        # kiểm: origin là <ten-ban>/shoplite, upstream là trandinhduc/shoplite
gh repo set-default <ten-ban>/shoplite               # BẮT BUỘC, xem cảnh báo dưới
gh repo set-default --view                           # phải in ra <ten-ban>/shoplite
git push -u origin main                              # đẩy main của bạn lên fork
gh repo view --web                                   # mở fork trên trình duyệt
```

> ⚠️ **Sau khi fork, `gh` nhắm repo của giảng viên** (thư mục có hai remote, `upstream` được ưu tiên) cho tới khi bạn
> chạy `gh repo set-default`. Bỏ qua lệnh đó thì `gh pr create` ở Bước 5 và bài 7.2 mở PR sang repo của giảng viên, và
> mọi lệnh `gh api repos/{owner}/{repo}/...` của Module 7 cũng gọi vào repo đó. Lệnh về secret và biến không dùng repo mặc định, nên trong
> Module 7 luôn ghi rõ `--repo <ten-ban>/shoplite` cho `gh secret` và `gh variable`. Mở PR bằng giao diện web thì đổi
> ô **base repository** về fork của bạn.

> ⚠️ `git push` bị từ chối với `non-fast-forward`: `main` của repo mẫu đã có commit mới hơn bản bạn clone. Chạy
> `git pull --no-rebase upstream main`, rồi `npm run check` và đẩy lại. Không dùng `--force`.

### 2b. Ba cài đặt của fork

Fork không mang theo secret, biến, collaborator hay cài đặt Actions của repo mẫu. Đặt lại:

```bash
REPO=<ten-ban>/shoplite
gh api -X PUT "repos/$REPO/collaborators/<ten-github-ban-cung-cap>" -f permission=push
gh api "repos/$REPO/actions/permissions" --jq .enabled          # true: Actions đang bật trên fork
gh api -X PUT "repos/$REPO/actions/permissions/fork-pr-contributor-approval" -f approval_policy=all_external_contributors
gh api "repos/$REPO/actions/permissions/fork-pr-contributor-approval" --jq .approval_policy   # all_external_contributors
```

Bạn cùng cặp nhận lời mời qua email hoặc ở <https://github.com/notifications> và bấm **Accept**.

Lệnh `PUT` ở trên là cài đặt **Settings › Actions › General › Approval for running fork pull request workflows from
contributors › Require approval for all external contributors**. Mặc định GitHub chỉ đòi phê duyệt với người đóng góp
lần đầu. Fork của bạn public: ai cũng mở được PR vào nó, và từ bài 7.3 một job của PR sẽ chạy trên máy bạn. Nếu
lệnh đầu in `false`, mở tab **Actions** của fork và bấm "I understand my workflows, go ahead and enable them".

### 2c. Token cho AI: `claude setup-token`

Từ bài 7.3, Claude Code chạy trên CI bằng **gói thuê bao Claude của bạn** (Pro, Max, Team hoặc Enterprise). CI không
mở được trình duyệt để đăng nhập, nên bạn tạo sẵn một token dài hạn rồi cất vào secret của fork. Mở một **terminal
riêng** (không gõ trong ô chat của Claude Code):

```bash
claude setup-token
```

Lệnh mở trình duyệt như khi `/login`; bấm **Authorize**. Xong, terminal in ra một token dài bắt đầu bằng
`sk-ant-oat01-`. Lệnh chỉ **in** token, không lưu ở đâu: chép ngay, rồi cất vào secret (lệnh hỏi giá trị và
**không** lưu vào lịch sử terminal):

```bash
gh secret set CLAUDE_CODE_OAUTH_TOKEN --repo <ten-ban>/shoplite     # dán token, Enter
gh secret list --repo <ten-ban>/shoplite             # thấy CLAUDE_CODE_OAUTH_TOKEN, không thấy giá trị
```

| Điều cần biết về token này | Hệ quả                                                                                                          |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Sống **một năm**           | Xóa secret khi học xong (bài 7.6). Xóa secret không thu hồi token, nhưng token không còn nằm ở đâu để ai dùng  |
| Gắn với **cá nhân bạn**    | Mọi lượt AI trên fork này tính vào hạn mức gói của bạn. Không gửi token cho bạn cùng cặp, không dùng chung repo |
| Chỉ gọi được model         | Lộ token thì người khác dùng được hạn mức gói của bạn trong một năm; họ không vào được tài khoản claude.ai       |
| Lệnh không lưu gì ở máy    | Phiên đăng nhập `claude` ở máy bạn không đổi; mất token thì chạy lại `claude setup-token` để tạo token mới       |

> 💰 Hạn mức dự trù: mỗi lần mở lại PR hay đẩy commit lên PR là một lần AI review (5 subagent; khi soạn bài 23 lượt,
> 138 giây) và, nếu có gate đỏ, một lần AI giải thích (3 lượt). Cả module khoảng 7 lần review và 4 lần giải thích,
> tính vào **hạn mức sử dụng của gói thuê bao**, không tính tiền theo token. Gói nhỏ có thể chạm giới hạn giữa buổi:
> khi đó bỏ chữ "BẮT BUỘC" ở mục (e) của prompt (bài 7.3, Bước 5) hoặc đổi sang khoá API của lớp.

> 💡 **Không có gói thuê bao Claude** (hoặc bạn dùng Gemini CLI): xin giảng viên khoá API của lớp, đặt
> `gh secret set ANTHROPIC_API_KEY --repo <ten-ban>/shoplite`, và trong `ai-review.yml` (bài 7.3), `ci.yml` (bài
> 7.4) thay dòng `claude_code_oauth_token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}` bằng
> `anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}`. Chỉ đặt **một** trong hai secret. Chi phí khi soạn bài:
> $0,28 - $0,91 mỗi lần review (trần $2,00), ~$0,19 mỗi lần giải thích, dự trù ~7 USD/học viên.

> ⚠️ Không dán token vào file nào, kể cả file tạm, và không dán vào ô chat của Claude (hook `scan-prompt` của
> Module 1 sẽ chặn). Gate `bao-mat` quét **cả lịch sử commit**: lỡ commit token thì xóa ở commit sau cũng không
> hết đỏ.

## Bước 3 - Cho AI sinh `ci.yml` với 4 gate (10')

Chép script gate và cấu hình đáp án (đây là phần "luật", không cần AI viết lại):

```bash
mkdir -p scripts/ci .github/workflows
cp ../lab-guides/module-7-cicd-ai/reference/scripts/ci/gate.mjs scripts/ci/
cp ../lab-guides/module-7-cicd-ai/reference/config/eslint.config.mjs .
printf '\n# Module 7 - file sinh ra khi chạy gate ở máy\ngate-*.log\ngate-*.json\n.ci/\nstorage/\n' >> .gitignore
git diff eslint.config.mjs                            # đọc 3 luật mới: BM-1, BM-2, KT-1
```

| Luật lint | Chặn gì                                                       | Vì sao                                                          |
| --------- | ------------------------------------------------------------- | --------------------------------------------------------------- |
| **BM-1**  | `new RegExp(<biến>)` trong `src/`                             | Khách gõ `tai(` là server lỗi 500; gõ `(.*.*)*!` là server treo |
| **BM-2**  | `dangerouslySetInnerHTML`                                     | Chèn HTML thô vào trang là mở cửa cho XSS                       |
| **KT-1**  | `import "node:fs"` ngoài `order-repository.ts`                | Quyết định kiến trúc của dự án: chỉ repository đọc/ghi file     |

Một quyết định đã thành luật lint thì **không còn phụ thuộc vào việc người review hay AI review có nhớ ra nó**.

Đặt sàn coverage. Đo trước, đừng đoán:

```bash
npx vitest run --coverage | grep -E "Statements|Branches|Functions|Lines"
```

Khi soạn bài, `main` đo được: Statements 72,97% · Branches 67,67% · Functions 71,89% · Lines 73,21%. Đặt sàn thấp
hơn khoảng 10 điểm, thêm vào `vitest.config.mts` ngay dưới dòng `exclude:` của `coverage`:

```ts
      // Sàn coverage của gate unit: chặn tụt mạnh, không nói được tính năng mới có test hay không.
      thresholds: { lines: 60, statements: 60, functions: 60, branches: 55 },
```

(Đáp án: [reference/config/vitest.config.mts](reference/config/vitest.config.mts).) Giờ cho Claude Code viết workflow.

**Prompt**

```text
Tạo .github/workflows/ci.yml cho ShopLite với đúng 4 job tên lint, unit, e2e, bao-mat (tên job sẽ là tên check
bắt buộc của main, không đổi). Yêu cầu:
- Chạy khi có pull_request và khi push lên main. Đẩy commit mới thì hủy lượt chạy cũ (concurrency).
- Quyền mặc định của workflow: contents: read. Không job nào cần quyền ghi.
- Mỗi job: actions/checkout (persist-credentials: false), actions/setup-node Node 22 có cache npm, npm ci,
  rồi gọi đúng một lệnh: node scripts/ci/gate.mjs <tên job>. Mỗi job có timeout-minutes.
- e2e: cài trình duyệt bằng npx playwright install --with-deps chromium trước khi chạy gate.
- bao-mat: checkout với fetch-depth: 0 (quét cả lịch sử). Cài gitleaks 8.30.1 bằng cách tải file
  gitleaks_8.30.1_linux_x64.tar.gz từ GitHub Releases và KIỂM sha256 = 551f6fc83ea457d62a0d98237cbad105af8d557003051f41f3e7ca7b3f2470eb
  trước khi chạy. Truyền tiêu đề và mô tả PR qua env (PR_TITLE, PR_BODY, BASE_SHA), không viết ${{ }} vào lệnh.
- Khi job đỏ, upload gate-<tên job>.* làm artifact tên gate-<tên job> (giữ 3 ngày); job e2e upload thêm test-results/.
- Ghim mọi action theo SHA 40 ký tự, ghi tag ở comment cuối dòng. Tra SHA thật bằng
  git ls-remote https://github.com/actions/checkout 'refs/tags/v7.0.1^{}' refs/tags/v7.0.1 (tương tự cho
  setup-node v7.1.0, upload-artifact v7.0.2). Có dòng ^{} thì đó mới là SHA của commit. Không tự bịa SHA.
Chỉ tạo file workflow, không sửa file khác.
```

Đọc file AI viết, đối chiếu với đáp án [reference/workflows/ci-4-gate.yml](reference/workflows/ci-4-gate.yml). Năm
chỗ AI hay viết sai:

- [ ] Quên `permissions: contents: read` ở đầu file (mặc định token của workflow có thể có quyền ghi).
- [ ] Ghim action bằng tag (`@v7`) thay vì SHA, hoặc **bịa** một SHA trông hợp lệ, hoặc lấy nhầm SHA của **tag có
      chú thích** thay vì SHA của commit. Kiểm bằng `git ls-remote <repo> 'refs/tags/<tag>^{}'`.
- [ ] Viết `${{ github.event.pull_request.title }}` thẳng vào `run:` (tiêu đề PR do người viết PR đặt, có thể là lệnh).
- [ ] Bỏ `fetch-depth: 0` ở job `bao-mat` → gitleaks chỉ thấy 1 commit cuối.
- [ ] Tải gitleaks mà không kiểm checksum.

Sai thì nhắn AI sửa, hoặc chép đáp án: `cp ../lab-guides/module-7-cicd-ai/reference/workflows/ci-4-gate.yml .github/workflows/ci.yml`.

Kết quả mong đợi:


> ⚠️ **Chạy gate trong terminal của bạn, không nhờ Claude Code chạy.** Next.js 16.4.2 đang có một cảnh báo bảo mật
> (mức moderate, không làm đỏ `npm audit --audit-level=high`). Khi lệnh do một AI agent chạy, `next dev` **dừng ở lần
> đầu** để nhắc nâng cấp, và gate `e2e` đỏ cả 14 test với `ERR_CONNECTION_REFUSED`. Trong log có dòng `[WebServer] ...
> This command stopped to show the upgrade recommendation`. Đó không phải lỗi của test hay của app: chạy lại trong

## Bước 5 - Thử gate bảo mật: khoá trong commit (5')

Làm trên nhánh bỏ đi. Khoá dưới đây là **khoá giả**, chỉ trông giống khoá thật:

```bash
git checkout -b thu-khoa
cat > src/lib/van-chuyen.ts <<'EOF'
// Tạm gọi thử API tính phí của hãng vận chuyển - sẽ chuyển sang biến môi trường sau
const SHIPPING_API_KEY = "gnx_live_7Hq2Lm9Vt4Rk8Wp3Zy6Bc1Nd5Fs0Jx";

export function shippingHeaders() {
  return { Authorization: `Bearer ${SHIPPING_API_KEY}` };
}
EOF
git add -A && git commit -m "feat: thử API phí vận chuyển"
node scripts/ci/gate.mjs bao-mat                     # ❌ gitleaks: generic-api-key ở src/lib/van-chuyen.ts:2
```

(Windows PowerShell: tạo file `src/lib/van-chuyen.ts` bằng VS Code với nội dung trên.) Giờ "sửa" bằng cách xóa file:

```bash
git rm src/lib/van-chuyen.ts && git commit -m "chore: bỏ file thử"
node scripts/ci/gate.mjs bao-mat                     # VẪN ❌: khoá còn trong lịch sử commit
git push -u origin thu-khoa && gh pr create --draft --fill
sleep 10 && gh pr checks --watch                     # bao-mat đỏ trên CI (chờ 10 giây để check kịp đăng ký)
```

Kiểm PR nằm ở **fork của bạn**, không phải repo của giảng viên: `gh pr view --json url --jq .url` phải in ra
`https://github.com/<ten-ban>/shoplite/pull/...`. PR nháp này lấy **số 1** trên fork của bạn, nên PR của đồng nghiệp ở bài 7.2 sẽ là số 2. Các bài sau không gõ số PR
mà tra theo tên nhánh, vào biến `$PR`. Khoá đã nằm trong lịch sử thì ai clone repo cũng lấy được. Với khoá **thật**, thứ tự đúng là: (1) **thu hồi khoá**
ở nhà cung cấp và tạo khoá mới, (2) đặt khoá mới vào `gh secret set`, (3) mới viết lại lịch sử. Bước (3) không
thay được bước (1). Dọn dẹp:

```bash
git checkout main
gh pr close thu-khoa --delete-branch                 # đóng PR, xóa nhánh ở cả GitHub và máy
git branch                                           # không còn thu-khoa
```

✅ **Checkpoint:** `gh repo set-default --view` in ra fork của bạn; `main` của fork có `ci.yml`, lượt chạy gần nhất
4 job xanh; `node scripts/ci/gate.mjs all` ở máy cũng 4 xanh; bạn đã thấy `bao-mat` đỏ cả sau khi xóa khoá; nhánh
`thu-khoa` đã xóa ở cả máy và GitHub; `gh secret list --repo <ten-ban>/shoplite` có `CLAUDE_CODE_OAUTH_TOKEN`; bạn
cùng cặp đã nhận lời mời; repo của giảng viên không có PR nào của bạn.
