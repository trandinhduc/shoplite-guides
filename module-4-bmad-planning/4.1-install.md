# 4.1 - Cài đặt BMAD Method vào ShopLite

**Thời lượng:** 25 phút · **Kết quả:** BMAD v6.12.4 cài vào ShopLite, agent trò chuyện và viết tài liệu
bằng tiếng Việt, `/bmad-help` chạy được.

## Lý thuyết nhanh: BMAD khác Spec Kit và OpenSpec ở đâu?

|                 | Spec Kit (Module 2) | OpenSpec (Module 3)         | **BMAD (Module 4-5)**                                           |
| --------------- | ------------------- | --------------------------- | --------------------------------------------------------------- |
| Đơn vị làm việc | Một feature         | Một change                  | Một **sản phẩm / initiative**: nhiều epic, nhiều story          |
| Bắt đầu từ      | Brief đã rõ yêu cầu | Brief đã rõ yêu cầu         | **Ý tưởng thô** → brainstorm → brief                            |
| Ai làm          | Một agent           | Một agent                   | **Một "đội" agent** có vai trò: Analyst, PM, UX, Architect, Dev |
| Tài liệu chính  | spec → plan → tasks | proposal → specs → tasks    | brief → PRD → UX → architecture → epics/stories → sprint-status |
| Review code     | `/speckit-converge` | `/opsx:verify`              | `bmad-code-review` với **4 lớp reviewer độc lập**               |
| Hợp với         | Tính năng 1-2 ngày  | Thay đổi nhỏ - vừa liên tục | Dự án/tính năng lớn cần lập kế hoạch nhiều tuần, nhiều người    |

## Bước 1 - Tạo nhánh và kiểm tra điều kiện (5')

Module 4 tách từ `main` (đã có `CLAUDE.md`, `AGENTS.md`, permissions và hooks của Module 1), giống Module 2-3.

```bash
cd shoplite
git checkout main && git status        # phải sạch
git checkout -b lab4-bmad
node --version                         # >= 22.12 (ShopLite yêu cầu; BMAD cần >= 20.12)
uv --version                           # BẮT BUỘC - mọi skill BMAD chạy script Python qua `uv run`
```

Chưa có `uv`: macOS/Linux `curl -LsSf https://astral.sh/uv/install.sh | sh`, Windows
`powershell -c "irm https://astral.sh/uv/install.ps1 | iex"`. uv tự tải Python 3.11+ khi cần, không cần
cài Python riêng.

> ⚠️ Thiếu `uv`, trình cài đặt chỉ **cảnh báo** rồi vẫn cài xong, nhưng tới lúc chạy `/bmad-build` sẽ
> HALT. Kiểm tra `uv` ngay từ bây giờ.

## Bước 2 - Cài BMAD (7')

Cách không tương tác (khuyên dùng trong lớp - mọi máy ra cùng kết quả):

```bash
npx bmad-method@6.12.4 install --directory . --modules bmm --tools claude-code \
  --user-name "<Tên của bạn>" \
  --communication-language Vietnamese --document-output-language Vietnamese --yes
```

(Windows PowerShell: viết trên một dòng, bỏ dấu `\`.)

| Cờ                           | Ý nghĩa                                                                                           |
| ---------------------------- | ------------------------------------------------------------------------------------------------- |
| `--modules bmm`              | Module "BMad Method" (agile: phân tích → lập kế hoạch → build). `core` luôn được cài kèm          |
| `--tools claude-code`        | Cài skill vào `.claude/skills/`. Xem các tool khác: `npx bmad-method@6.12.4 install --list-tools` |
| `--communication-language`   | Ngôn ngữ agent trò chuyện với bạn                                                                 |
| `--document-output-language` | Ngôn ngữ của brief, PRD, epics... sinh ra                                                         |
| `--yes`                      | Nhận mặc định cho mọi câu hỏi còn lại (thư mục output `_bmad-output`)                             |

Muốn xem đủ các câu hỏi, chạy `npx bmad-method@6.12.4 install` không có cờ: chọn module **BMad Method**,
tích **Claude Code** ở bước _Integrate with_, trả lời tên, tên dự án, ngôn ngữ, chọn _Express Setup_, và
trả lời **No** cho câu hỏi cài _deprecated compatibility shim_.

Kết thúc thành công sẽ có khung **"BMAD is ready to use!"**.

## Bước 4 - Cho phép lệnh `uv run` của BMAD (3')

Settings của Module 1 đặt `"defaultMode": "default"`, nên mỗi lần skill chạy `uv run ...` bạn sẽ bị hỏi
quyền - một phiên PRD có thể hỏi vài chục lần. Thêm 3 rule vào mảng `allow` của **file cá nhân**
`.claude/settings.local.json` (đã có từ bài 1.2 - không commit, không đụng settings của team):

```json
{
  "permissions": {
    "allow": ["Bash(uv run *)", "Bash(git rev-parse *)", "Bash(git show *)"]
  }
}
```

> ⚠️ Đánh đổi (nhớ lại bài 1.2): `Bash(uv run *)` cho phép **mọi** lệnh `uv run`, kể cả `uv run curl ...` -
> lách được rule `deny` `Bash(curl *)`, vì rule so khớp theo chuỗi lệnh. Chấp nhận được trong lab; team khó
> tính hơn có thể bỏ rule này và duyệt từng lần.

Giữ nguyên rule `ask` của `git commit` từ Module 1: ở Module 5, `bmad-build` sẽ **tự commit local** sau
khi xong một story - bạn sẽ thấy hộp thoại xin quyền commit, đọc message rồi mới đồng ý.

Khởi động lại Claude Code (`/exit` rồi `claude`), chấp nhận _Trust this folder_ nếu được hỏi.

## Bước 5 - Hỏi `/bmad-help` (5')

`bmad-help` đọc danh mục skill, cấu hình và các tài liệu đã có trong `_bmad-output/` để chỉ ra
**bạn đang ở đâu và bước tiếp theo là gì**.

**Prompt**

```text
/bmad-help Tôi có một dự án Next.js 16 đang chạy là ShopLite (đọc AGENTS.md). Tôi có một ý tưởng tính năng
lớn còn mơ hồ, cần đi từ ý tưởng tới backlog có epic, story và sprint. Tôi nên bắt đầu từ đâu và đi qua
những skill nào?
```

Kết quả mong đợi (đại ý): dự án đã có sẵn code (brownfield) → làm rõ ý tưởng (`bmad-brainstorming`,
`bmad-party-mode`) → `bmad-product-brief` → `bmad-prd` → `bmad-ux` (vì có giao diện) → `bmad-architecture`
→ `bmad-create-epics-and-stories` → `bmad-sprint-planning`; và lời khuyên **mở phiên mới cho mỗi skill**.

> 💡 **Mở phiên mới cho mỗi skill** (`/clear` hoặc thoát rồi mở lại `claude`): các tài liệu đã nằm trên
> đĩa, skill sau sẽ đọc lại. Phiên sạch giúp agent không bị "nhiễu" bởi hội thoại cũ và tiết kiệm token.

## Bước 6 - Commit (2')

Hook **format-file** của Module 1 chạy Prettier cho mọi file `.md` mà agent sửa - kể cả tài liệu BMAD và
spec của story (làm diff nhiễu, và làm `npm run format:check` báo lỗi với file skill của BMAD). Cho Prettier
bỏ qua các thư mục của BMAD:

```bash
printf '_bmad\n_bmad-output\n.claude/skills\n' >> .prettierignore
```

```bash
git add .claude/skills _bmad .prettierignore
git status --short _bmad              # chỉ _bmad/custom/*.user.toml được gitignore sẵn
git commit -m "chore: install BMAD Method v6.12.4 (bmm, claude-code, Vietnamese)"
```

> 💡 `_bmad/config.user.toml` (tên của bạn, ngôn ngữ) **vẫn được commit**. Làm theo nhóm chung một repo thì
> mỗi người nên đặt giá trị cá nhân trong `_bmad/custom/config.user.toml` (đã gitignore), file này được ưu
> tiên hơn.

✅ **Checkpoint:** gõ `/bmad-` thấy danh sách skill; `/bmad-help` trả lời bằng tiếng Việt; `git log` có
commit cài BMAD.

## Mở rộng (tùy chọn) - `bmad-project-context` cho dự án đang chạy

BMAD có skill quản lý context file. Vì `AGENTS.md` của ShopLite đã viết tay ở Module 1, skill sẽ chạy ở
chế độ **adopt** (chuyển một file viết tay sang dạng được BMAD quản lý): kiểm tra từng quy tắc với
`package.json` và code thật, hỏi bạn phần còn thiếu, rồi trình ra một **ledger** - với mỗi quy tắc cũ:
giữ / viết lại / chuyển chỗ / tự động hóa / xóa - cùng khối mới.

```text
/bmad-project-context Dự án đã có AGENTS.md viết tay và CLAUDE.md import nó. Hãy adopt: kiểm chứng các quy
tắc hiện có với code, chỉ ra quy tắc nào sai hoặc đã cũ. Trình ledger cho tôi duyệt trước khi ghi.
```

Khi bạn duyệt, các quy tắc được giữ sẽ được **chuyển vào** giữa `<!-- bmad:context -->` và
`<!-- /bmad:context -->` (kèm dòng ghi ngày và commit SHA), và skill có thể đề xuất rút `CLAUDE.md` còn
`@AGENTS.md`. Đọc kỹ ledger, từ chối mục nào bạn muốn giữ nguyên ngoài marker (ví dụ mục _Dành riêng cho
Claude Code_ trong `CLAUDE.md`). Skill **không tự commit**. So sánh với `AGENTS.md` của Module 1: nó phát
hiện thêm được gì?
