# 4.5 - Thiết kế UX và design system với `/bmad-ux`

**Thời lượng:** 25 phút · **Kết quả:** `DESIGN.md` (design token + component) và `EXPERIENCE.md` (luồng,
trạng thái, accessibility), kèm 1-2 mockup HTML cho màn hình quan trọng.

## Lý thuyết nhanh

`bmad-ux` sinh ra **hai tài liệu xương sống** (spine) và vài sản phẩm phụ:

| File                              | Nói về                         | Nội dung chính                                                                                                                                                                                                    |
| --------------------------------- | ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DESIGN.md`                       | Giao diện **trông thế nào**    | Frontmatter YAML chứa token: `colors`, `typography`, `rounded`, `spacing`, `components`. Thân: Brand & Style · Colors · Typography · Layout & Spacing · Elevation & Depth · Shapes · Components · Do's and Don'ts |
| `EXPERIENCE.md`                   | Giao diện **hoạt động ra sao** | Foundation · Information Architecture · Voice and Tone · Component Patterns · State Patterns · Interaction Primitives · Accessibility Floor · Key Flows                                                           |
| `.working/*.html`, `*.excalidraw` | Bản thử                        | Bảng màu, hướng thiết kế, wireframe Excalidraw, mockup HTML màn hình chính                                                                                                                                        |

`DESIGN.md` theo định dạng [design.md](https://github.com/google-labs-code/design.md) của Google Labs, nên
đọc được bằng cả người và công cụ (Google Stitch, agent sinh UI...). Khi dự án đã có hệ thống UI, `DESIGN.md`
**chỉ ghi phần khác biệt (delta)** thay vì định nghĩa lại từ đầu.

> 💡 PRD có thể đi thẳng sang architecture. Làm UX khi tính năng có **màn hình mới** (ý tưởng A: trang quản
> trị; B: trang tra cứu; C: trang flash sale và đồng hồ đếm ngược).

## Bước 1 - Gọi `/bmad-ux` với design hiện có của ShopLite (15')

Mở phiên mới.

**Prompt**

```text
/bmad-ux Tạo UX cho tính năng trong PRD _bmad-output/planning-artifacts/prds/<thư mục>/prd.md.
Đây là sản phẩm đang chạy, đã có design system ngầm định - hãy đọc code để ghi nhận, KHÔNG thiết kế lại:
- Tailwind CSS v4, font Be Vietnam Pro (src/app/layout.tsx, src/app/globals.css)
- Màu chính indigo-600, trung tính slate, lỗi/nguy hiểm rose-600, thành công emerald
- Nút: src/components/ui/button.tsx (primary/secondary/ghost/danger, rounded-xl, h-8/h-10/h-12)
- Thẻ: bg-white rounded-2xl shadow-sm ring-1 ring-slate-200; badge trạng thái đơn:
  src/features/orders/components/order-status-badge.tsx; icon lucide-react; ảnh sản phẩm là emoji trên gradient
DESIGN.md chỉ ghi token hiện có + phần bổ sung cho màn hình mới (delta). Giao diện tiếng Việt, mobile 390px.
```

Trả lời các câu hỏi (stakes: **internal**; working mode: **Coaching path** nếu muốn thấy các công cụ sáng
tạo, **Fast path** nếu thiếu giờ). Ở Coaching path, agent có thể mở trên trình duyệt:

- `color-themes-*.html` - vài biến thể màu cho phần mới (ví dụ màu cho trạng thái mới, nhãn flash sale).
- `direction-*.html` - các hướng bố cục khác nhau cho màn hình chính.
- `ia-*.excalidraw`, `flow-*.excalidraw` - wireframe, mở bằng [excalidraw.com](https://excalidraw.com).

Chọn một hướng, nói rõ vì sao. Khi agent hỏi về **user journey** (Key Flows), dùng lại nhân vật đã kể ở PRD.

## Bước 2 - Finalize và mockup (7')

Ở Finalize, agent sẽ:

1. Đề nghị **validate** (tùy chọn): kiểm tra Flow coverage, Token completeness (màu thiếu mã hex là lỗi
   nghiêm trọng), Component coverage, State coverage, Visual reference coverage.
2. Render **key-screen mockup**: HTML 1:1 cho 2-4 màn hình quan trọng nhất (ví dụ danh sách đơn quản trị,
   chi tiết đơn có timeline).
3. Hỏi: _"Những màn hình này sẽ được build chỉ từ bảng spine - màn nào cần hình tham chiếu?"_ → chọn màn hình
   có nhiều trạng thái nhất.

Kết quả: `_bmad-output/planning-artifacts/ux-designs/ux-<dự-án>-<ngày>/`

```text
DESIGN.md         # status: final, token trong frontmatter YAML
EXPERIENCE.md     # status: final, sources: [đường dẫn PRD]
mockups/*.html    # mockup được giữ lại
wireframes/       # wireframe được giữ lại
.working/         # các bản thử (có thể không commit)
```

## Bước 3 - Review (2')

- [ ] Token trong `DESIGN.md` khớp code thật, không bịa màu mới cho phần đã có. Định dạng design.md yêu cầu
      token màu là mã **hex**, còn Tailwind v4 định nghĩa màu bằng OKLCH: indigo-600 là
      `oklch(51.1% 0.262 276.966)` ≈ `#4f39f6` - **không phải** `#4f46e5` của Tailwind v3 (kiểm tra bằng
      `grep color-indigo-600 node_modules/tailwindcss/theme.css`). Token ghi hex, có thể ghi kèm giá trị OKLCH
      và tên class Tailwind ở phần thân mục _Colors_.
- [ ] `EXPERIENCE.md` có **State Patterns** cho trạng thái rỗng, đang tải, lỗi, và trạng thái nghiệp vụ
      (ví dụ nút chuyển trạng thái bị vô hiệu với đơn đã hủy).
- [ ] _Accessibility Floor_ có: label cho form, focus nhìn thấy được, không dùng **chỉ màu** để phân biệt trạng thái.
- [ ] Mở mockup HTML ở chế độ mobile 390px (DevTools): không vỡ bố cục.
