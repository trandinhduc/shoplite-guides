# 8.4 - Chạy tự động, hoặc chạy tay có nhật ký

**Thời lượng:** 12 phút · **Kết quả:** agent nằm trong PR `lab8-agent`, gate `bao-mat` xanh. Chọn một trong hai hướng:
**workflow** (agent tự kích hoạt, ra GitHub Release **nháp**, `kiem-tra-workflow.mjs` 0 lỗi) hoặc **chạy tay** (đã đọc nhật ký và
thu hẹp quyền thêm một lần).

> 🎬 **Gợi ý demo (3'):** `gh workflow run release-notes.yml -f tag=v0.2.0` rồi `gh run watch`. Trong lúc chờ, đọc hai job:
> _"Job viết có khoá nhưng chỉ đọc repo. Job đăng có quyền ghi nhưng không gọi AI. Kẻ chèn được chỉ dẫn vào mô tả PR cũng
> không có quyền ghi để dùng."_ Xong mở tab **Releases**: bản nháp, chưa ai thấy cho tới khi người bấm công bố.

## Lý thuyết nhanh

### Chọn hướng nào

| Việc của bạn                                       | Hướng                                     |
| -------------------------------------------------- | ----------------------------------------- |
| Dữ liệu có trên GitHub (PR, Actions, code)         | Workflow                                  |
| Dữ liệu chỉ có trên máy (`storage/orders.json` của `don-sang`) | Chạy tay                      |
| Chạy ra thứ có hiệu lực ngay, chưa có chỗ người duyệt | Chạy tay, tới khi có chỗ duyệt         |
| Chỉ ra nháp cho chính mình đọc                     | Chạy tay là đủ                            |

### Workflow của bản mẫu

`.github/workflows/release-notes.yml` có hai job, cùng cách tách với bài 7.4:

| Job    | Cầm khoá     | Quyền GitHub                       | Gọi AI | Việc                                                    |
| ------ | ------------ | ---------------------------------- | ------ | ------------------------------------------------------- |
| `viet` | Có           | `contents: read`, `pull-requests: read` | Có | Gom PR bằng script, rồi AI viết nháp, trả qua `structured_output` |
| `dang` | Không        | `contents: write`                  | Không  | Tạo hoặc sửa GitHub Release dạng **nháp**               |

Release luôn là nháp. Đăng thẳng thì "sai thì sửa được" chỉ còn trên lý thuyết.

Ba điểm khác với lệnh chạy ở máy:

| Ở máy (`cau-hinh.json`)        | Trên CI (`claude_args`)                                                | Vì sao                                                     |
| ------------------------------ | ---------------------------------------------------------------------- | ---------------------------------------------------------- |
| `--setting-sources project`    | `--setting-sources user`, skill chép sang `~/.claude/skills`           | Máy chạy trống; hook và luật của dự án không nạp, như Module 7 |
| Có hook `log-cong-cu.mjs`      | Không có hook. Nhật ký là output của action                            | Cùng lý do                                                 |
| `claude -p` trực tiếp          | `anthropics/claude-code-action`, token vào `claude_code_oauth_token`   | Luật R4: khoá ở `env:` thì mọi bước trong job đều đọc được |

Workflow dùng lại secret `CLAUDE_CODE_OAUTH_TOKEN` bạn đặt ở bài 7.1. Nếu ở Module 7 bạn dùng khoá API của lớp, đổi dòng
xác thực thành `anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}`. Đã xóa secret sau Module 7 thì tạo lại bằng
`claude setup-token` và `gh secret set CLAUDE_CODE_OAUTH_TOKEN --repo <ten-ban>/shoplite`. Cả hai job chạy trên máy của
GitHub (`ubuntu-latest`): runner tự dựng của bài 7.3 chỉ dành cho job `review`.

### Vì sao không kích hoạt bằng đẩy tag

- `claude-code-action` v1.0.259 **không nhận** sự kiện `push`, kể cả đẩy tag. Nó nhận `workflow_dispatch` và `schedule`.
- Tự cài CLI rồi gọi `claude -p` trong `run:` thì phải đặt khoá ở `env:`. `kiem-tra-workflow.mjs` báo lỗi R4 và gate `bao-mat`
  đỏ. Đã thử: 1 lỗi R4. **Không sửa luật để cho qua.**

Nên bản mẫu dùng hai cách kích hoạt:

```yaml
on:
  workflow_dispatch:
    inputs:
      tag: { description: "Tag mới, ví dụ v0.2.0", required: true }
  schedule:
    - cron: "45 1 * * 1" # 08:45 thứ Hai giờ Việt Nam
```

> ⚠️ GitHub dùng giờ **UTC**, Việt Nam là UTC+7. 08:45 sáng là `45 1`, không phải `45 8`. Lịch có thể chạy trễ vài phút tới vài
> chục phút. Repo public không có hoạt động 60 ngày thì GitHub tắt lịch.

> ⚠️ `workflow_dispatch` và `schedule` **chỉ chạy khi file nằm ở nhánh mặc định**. Vì `main` đã khoá, `gh workflow run` chỉ dùng được
> sau khi PR `lab8-agent` merge.

## Hướng A - Workflow (dữ liệu trên GitHub)

### Bước 1 - Viết workflow (4')

Làm `release-notes` thì chép mẫu. Việc khác thì cho AI viết theo mẫu:

```bash
cp "$M8/workflows/release-notes.yml" .github/workflows/release-notes.yml
```

**Prompt**

```text
Đọc .github/workflows/release-notes.yml và .github/workflows/ci.yml (job phan-tich-loi và dang-phan-tich). Tạo
.github/workflows/<tên>.yml cho agent trong .claude/evals/<tên>/agent_design.md, giữ đúng cách tách hai job:

- permissions: {} ở đầu file. Job cầm khoá chỉ có quyền đọc. Job đăng có quyền ghi, không cầm khoá, không gọi AI.
- Kích hoạt theo mục 3 của bản thiết kế: workflow_dispatch và/hoặc schedule. Cron theo giờ UTC, ghi chú giờ Việt Nam.
- Bước gom dữ liệu chạy trước, không gọi AI. Chép skill sang ~/.claude/skills.
- Bước AI dùng anthropics/claude-code-action ghim SHA như ai-review.yml, đủ 4 tham số. claude_args có --permission-mode dontAsk,
  --setting-sources user, --strict-mcp-config, --max-turns và --max-budget-usd lấy từ mục 7, --allowedTools đúng mục 6,
  --disallowedTools có Read(./.git/**), --json-schema cho đầu ra.
- Job có timeout-minutes lấy từ mục 7.
- Kết quả có hiệu lực ra ngoài thì phải ở dạng nháp hoặc qua người duyệt. Không tự merge, không tự công bố.
```

```bash
node scripts/ci/kiem-tra-workflow.mjs        # 0 lỗi
```

Đọc lại khối `permissions` và `claude_args` của cả hai job.

### Bước 2 - Mở PR (3')

```bash
git add scripts/agent .claude .github/workflows
git status                                   # không có .env, không có .claude/logs
git commit -m "feat(agent): <tên> - bản thiết kế, năm ca thử, workflow"
git push -u origin lab8-agent
gh pr create --base main --fill
```

Commit cả `ket-qua/`: giảng viên và bạn cùng cặp chấm lại được bằng `--cham-lai`, không tốn tiền. Đã quét thử bằng gitleaks 8.30.1 với
`.gitleaks.toml` của Module 7: không báo gì.

Trên PR, mong đợi:

- Bốn gate chạy như mọi PR. `bao-mat` xanh; mục `[AT-2]` liệt kê các file `.claude/` và `.github/workflows/`: bạn cùng cặp **phải đọc riêng** các file này.
- `AI review` có thể báo `[AT-1]` vì ca 3 có câu mồi cố ý. Trả lời ngay dưới nhận xét: _"Ca thử cố ý, xem `ca.json`."_ Không xóa câu mồi.
- `release-notes.yml` chưa chạy, vì chưa nằm trên `main`.

### Bước 3 - Sau khi merge: kích hoạt thật (5')

Bạn cùng cặp duyệt (có nhận xét thật, như bài 7.6), bạn merge. Rồi:

```bash
git checkout main && git pull
git push origin v0.1.0 v0.2.0
gh workflow run release-notes.yml -f tag=v0.2.0
gh run watch "$(gh run list --workflow release-notes.yml --limit 1 --json databaseId --jq '.[0].databaseId')"
gh release view v0.2.0 --json isDraft,body --jq '.isDraft, .body' | head -20
```

Mong đợi: `isDraft` là `true`, nội dung đúng mẫu. Thử xem job `viet` ở tab **Actions**: tổng lượt, tổng tiền.

> ⚠️ Bản mẫu **chưa chạy trên GitHub thật** khi soạn bài, giống Module 7 lúc soạn. Phần AI với `--json-schema` đã chạy thật ở máy, ra đúng
> trường `release_note`. Workflow đã qua `kiem-tra-workflow.mjs`. `lay-pr.mjs` đã chạy với một `gh` giả lập, chưa gọi `gh` thật. Giờ lớp là
> lần đầu của bạn: đỏ thì đọc log, sửa qua PR.

> 💡 Thiếu giờ (mục cắt của lớp): PR chưa merge thì dừng ở `kiem-tra-workflow.mjs` 0 lỗi; merge và `gh workflow run` làm sau giờ học.

> 💡 Lịch sáng thứ Hai tạo Release nháp tên `nhap-tuan-nay`. Trước khi công bố, người duyệt **đổi tên tag** cho đúng số bản.

## Hướng B - Chạy tay (dữ liệu trên máy)

### Bước 1 - Đọc nhật ký, thu hẹp quyền (6')

Chạy agent một lần trên dữ liệu thật:

```bash
claude -p "/don-sang" --model sonnet --permission-mode dontAsk --setting-sources project --strict-mcp-config \
  --mcp-config .claude/evals/don-sang/mcp.json --tools Read \
  --allowedTools mcp__shoplite-don__liet_ke_don_cho mcp__shoplite-don__de_xuat_xu_ly \
  --max-turns 12 --max-budget-usd 0.30

tail -5 .claude/logs/cong-cu.jsonl           # agent đã gọi những gì?
cat storage/de-xuat-don.json                 # hàng chờ: mọi dòng đều cho-duyet
```

Đối chiếu nhật ký với mục 6. Mỗi dòng trong mục 6 có được gọi không? Dòng nào không được gọi qua cả năm ca thì **bỏ**, rồi chạy lại
`soat-quyen.mjs` và năm ca (vân tay đã đổi). Ghi vào **Bảng C**.

> 💡 Người học hay bất ngờ khi đọc nhật ký: agent gọi ít hơn hoặc nhiều hơn mình tưởng. Đó là lý do có hook, không dựa vào lời agent kể.

### Bước 2 - Mở PR (6')

Giống Bước 2 của hướng A, trừ file workflow:

```bash
git add scripts/agent .claude
git commit -m "feat(agent): <tên> - bản thiết kế, năm ca thử"
git push -u origin lab8-agent
gh pr create --base main --fill
```

`storage/` đã nằm trong `.gitignore`, nên đơn thật và hàng chờ không lên GitHub. Ca thử chỉ dùng đơn giả.
